# 글로벌 상용 ITAM / 엔드포인트 인벤토리 제품 조사 노트 (Agent + Server + Web FE 아키텍처 기준)

> 조사 시점: 2026-10-11. 조사 환경의 네트워크 정책상 벤더 문서 페이지를 직접 열람(fetch)할 수 없었고, 웹 검색 엔진이 반환한 페이지 발췌(extract)만 활용했다. 따라서 모든 사실은 "검색 결과에 포함된 발췌"를 근거로 하며, 수치/포트/주기 등 세부값은 도입 전 반드시 원문 문서에서 재확인해야 한다. 벤더 마케팅 페이지 기반의 주장은 "(벤더 주장)"으로 표시했다.
>
> 주요 제품 변동: Snow Software는 2024-02-15 Flexera에 인수 완료(통합 중), Device42는 2024년 Freshworks에 약 $230M에 인수됨. Gartner는 SAM 툴에 대해 Magic Quadrant가 아닌 "Market Guide for Software Asset Management Tools"(최신판 2026-01-15)를 발행한다. NinjaOne은 2026-07-22 ServiceNow와 공식 통합을 발표했다.

## 핵심 질문 1. 제품별 PC 에이전트: 수집 항목, 통신 방식, 에이전트리스 옵션, 풋프린트, 지원 OS, 배포 방식, 자동 업데이트, 오프라인 캐시

### Takeaway
"Windows 에이전트 + 중앙 서버 + 웹 FE"를 가장 투명하게 문서화한 참조 모델은 Lansweeper(LsAgent: .NET Framework 4.8, 서버 9524/TCP 직결 또는 443 클라우드 릴레이, 최소 1시간 주기), ManageEngine(Endpoint Central 에이전트: HTTPS 8383, 90분 정책 폴링, 스캔은 서버 스케줄), Flexera/Snow(암호화 파일 업로드 + 10분 heartbeat + 1일 1회 스캔) 세 계열이다. SaaS형(NinjaOne 60초 페이로드/영속 WAMP 연결, Intune Device Inventory Agent 24시간 주기, Freshservice 변경 시 즉시 + 주 1회, Action1 outbound HTTPS)은 "에이전트가 항상 아웃바운드로 push"하는 모델이고, ServiceNow ACC는 MID Server의 websocket(8800)에 push하는 하이브리드다.

### Cited Findings

**Lansweeper (LsAgent / 신규 IT Agent)**
- LsAgent는 Windows, Mac, Linux에 설치하는 소형 경량 애플리케이션으로, 자산 데이터를 로컬에서 수집한 뒤 Lansweeper 설치본으로 전송한다. Sites(클라우드) 사용자용으로 신규 "IT Agent"가 프리뷰로 제공된다 — [Lansweeper docs: introduction to lsagent](https://docs.lansweeper.com/classic/docs/introduction-to-lsagent-for-windows-linux-and-mac.md)
- 통신: LsAgent는 먼저 스캐닝 서버의 listen 포트(기본 9524, Configuration > Server Options)로 직접 전송을 시도하고, 실패 시 Azure에 호스팅된 클라우드 릴레이(lsagentrelay.lansweeper.com)로 보낸다. 릴레이 경로에서는 스캐닝 서버가 443 아웃바운드로 릴레이에 접속해 데이터를 가져오며, 릴레이 데이터는 암호화 저장 후 서버가 회수하면 삭제된다. 릴레이 설정은 Classic 웹 콘솔에서만 켤 수 있다 — [Lansweeper docs: install LsAgent on Windows](https://docs.lansweeper.com/classic/docs/install-lsagent-on-a-windows-computer); 보조: [third-party troubleshooting blog (TCP 9524)](https://n8n.bitcamp.ge/blog/troubleshoot-lansweeper-lsagent-not-scanning-issues-1767648811)
- 스캔 주기: 콘솔의 Scanning > LsAgent Scanning에서 머신을 그룹으로 나누고 그룹별 스케줄을 지정. 최소 스캔 간격은 1시간(더 짧게 설정해도 1시간으로 동작). 커뮤니티 구 게시글은 4시간 최소를 언급(구버전 추정). 기본값은 1일 1회(커뮤니티) — [Lansweeper docs: install LsAgent](https://docs.lansweeper.com/classic/docs/install-lsagent-on-a-windows-computer); [Lansweeper community: LsAgent and relay scanning time](https://community.lansweeper.com/t5/general-discussions/lsagent-and-relay-scanning-time/m-p/69651)
- 항목별 갱신 주기(scanned item intervals)는 LsAgent에는 적용되지 않으며, LsAgent 재스캔 시 활성화된 모든 스캔 항목을 항상 갱신한다 — [Lansweeper docs: manage scanned item intervals](https://docs.lansweeper.com/classic/docs/manage-scanned-item-intervals)
- 에이전트 하드웨어 요구사항은 문서화되어 있지 않다(스캔이 1분 미만으로 끝나 영향이 미미하다는 직원 답변). 스캔 서버 측은 LsAgent 스캔 처리를 위해 최소 1GB 또는 여유 메모리 10%를 권장(블로그는 4GB 여유 권장) — [Lansweeper community: LsAgent documentation and best practices](https://community.lansweeper.com/t5/forum/lsagent-documentation-and-best-practices/m-p/66003)
- 수집 범위: 에이전트리스 Windows 스캔과 동일한 하드웨어/소프트웨어 데이터를 수집하지만 Exchange Server 정보는 가져오지 못한다 — [Lansweeper community](https://community.lansweeper.com/t5/forum/lsagent-documentation-and-best-practices/m-p/66003)
- 지원 OS/런타임: Windows 클라이언트는 .NET Framework 4.8 이상 필요. Windows Server 2008 R2 SP1 / 2012 / 2012 R2 / 2016 / 2019 / 2022(64-bit) 지원(.NET 4.8 전제). 설치 프로그램이 microsoft.com에 접속해 .NET을 설치할 수 있으며 재부팅이 필요할 수 있다. LsAgent 8.x(Lansweeper 8.4.100)부터 최소 .NET 4.8로 상향되어 vanilla Windows 8 등 구형 지원 중단. Linux/Mac용 LsAgent는 10.2부터 .NET 6.0 동봉 — [Lansweeper docs: LsAgent installation requirements](https://docs.lansweeper.com/classic/docs/lsagent-installation-requirements); [Lansweeper community: .NET version for LsAgent](https://community.lansweeper.com:443/t5/forum/net-version-for-lsagent/m-p/46747)
- 모니터: 모니터 데이터는 Windows PC의 레지스트리에서 읽어 연결 PC 스캔 시 자산으로 추가. 제조사, 모델, 시리얼, 화면 크기/해상도, USB 허브 정보 수집. Dell/Fujitsu/HP/Lenovo 등은 제조사 보증 정보를 조회 시도 — [Lansweeper: monitor asset](https://www.lansweeper.com/asset/monitor/)
- 보증(warranty) 조회: Dell, Fujitsu, HP, IBM, Lenovo, Toshiba 등을 점검하며 out-of-warranty 리포트 제공. 조회는 자산 Summary 탭의 모델/시리얼/(일부)SKU를 벤더 웹사이트에 제출하는 방식이고, 절차는 Lansweeper 서비스에 하드코딩되어 변경 불가 — [Lansweeper: warranty check](https://www.lansweeper.com/product/features/warranty-check/); [Lansweeper community: warranty info](https://community.lansweeper.com/t5/general-discussions/warranty-info-for-scanned-asset/td-p/56537)
- 시리얼은 WMI Win32_BIOS에서 수집(직원 답변) — [Lansweeper community: asset tag numbers](https://community.lansweeper.com/t5/general-discussions/asset-tag-numbers/m-p/9238)
- 신규 IT Agent(프리뷰): 2023 Fall Release("Ename")에서 "Cloud-First IT Agent" 프리뷰 공개. LsAgent와 LsPush의 장점을 결합, Windows/Linux/macOS 지원, 사일런트 설치 가능, 데이터는 클라우드 Site로 직접 전송. 이후 커뮤니티 게시글에 3개 OS 자동 업데이트, .NET 6.0 Windows 빌드, Cloud API를 통한 온디맨드 스캔이 언급됨. Intune 등 사일런트 배포가 권장 경로 — [Lansweeper community: IT Agent preview](https://community.lansweeper.com/t5/product-discussions/new-preview-capability-track-your-hard-to-reach-assets-using-it-agent-the/td-p/68280/page/9); [Lansweeper blog ?p=21682](https://www.lansweeper.com/?p=21682)
- 사용자 로그온 시 LsAgent 실행 스케줄링 팁이 공식 블로그에 있음(로그인 사용자 추적 보완용으로 추정) — [Lansweeper blog: schedule LsAgent at user logon](https://www.lansweeper.com/blog/pro-tips/schedule-lsagent-to-run-at-user-logon/)

**ManageEngine AssetExplorer / Endpoint Central 에이전트**
- AssetExplorer 에이전트 스캔은 TCP 9000 단일 포트만 필요(Admin -> Agent settings -> Agent Configuration -> Agent Port에서 변경). 에이전트는 Windows만 지원한다는 도움말과, Windows/Linux/macOS를 지원한다는 자료가 혼재(후자는 Endpoint Central 에이전트 기준으로 추정) — [ManageEngine AssetExplorer FAQ](https://www.manageengine.com/products/asset-explorer/faq.html); [AssetExplorer help: agent mode](https://www.manageengine.cn/products/asset-explorer/help/scanning_it_assets/agent-mode.html)
- AssetExplorer의 에이전트 구성요소는 Endpoint Central이며 Windows 서버에만 설치 가능. Linux AssetExplorer 환경에서는 Endpoint Central을 별도 Windows 서버에 설치해 UEM Products 통합 페이지에서 연동. 3만 노드마다 별도 원격 서버 권장 — [ManageEngine AssetExplorer system requirements](https://www.manageengine.com/ca/products/asset-explorer/system_requirements.html); [AssetExplorer help: agent-based scanning for fresh installations](https://manageengine.com/products/asset-explorer/help/scanning_it_assets/dc-agent-for-fresh-installation.html)
- Endpoint Central 포트: 8383(에이전트-서버 HTTPS, 서버 인바운드), 8027(서버→에이전트 온디맨드 작업), 8443/8444(원격 데스크톱/시스템 매니저/채팅/파일 전송). 인벤토리 스캔에는 8020(HTTP) 또는 8383(HTTPS) 인바운드 개방, DCOM 활성화, UAC/Remote UAC 비활성화, WMI 정상 구성 필요 — [ServiceDesk Plus help: dc agent](https://help.servicedeskplus.com/dc-agent-sdp); [ManageEngine Desktop Central asset management FAQ](https://www.manageengine.com/products/desktop-central/asset-management-training-faq.html)
- 에이전트 정책 갱신 주기는 약 90분(배포 없을 때), 인벤토리 스캔은 서버에서 예약한 시각에 실행 — [ManageEngine Desktop Central: agent footprint](https://www.manageengine.com/products/desktop-central/agent-footprint.html)
- 소프트웨어 미터링: 미터링 규칙은 다음 에이전트-서버 접촉 시 적용되고 리포트는 규칙 생성 24시간 후 생성 — [ManageEngine Desktop Central asset management FAQ](https://www.manageengine.com/products/desktop-central/asset-management-training-faq.html)
- AssetExplorer 기능: 구매 vs 설치 라이선스 추적(예약 스캔으로 미승인 설치 플래그), 발견된 설치에 라이선스 자동 할당, CI 관계를 유지하는 CMDB(발견 자산/사용자 자동 동기화), 바코드/QR/RFID 스캐너로 자산 임포트, 소프트웨어 사용 빈도 분류(rarely/occasionally/frequently), PO 전체 수명주기, 계약 관리 모듈, 드래그앤드롭 캔버스로 자산 상태별 자동 액션을 설계하는 수명주기 — [ManageEngine AssetExplorer cloud](https://www.manageengine.com/products/asset-explorer/cloud.html); [ManageEngine AssetExplorer (IN)](https://www.manageengine.com/in/products/asset-explorer/) (벤더 주장)
- 클라우드 에디션은 신규 발견 자산을 CMDB에 CI로 자동 생성 — [ManageEngine blog: cloud AssetExplorer](https://www.manageengine.com/blog/general/unveiling-cloud-based-manageengine-assetexplorer-our-enterprise-it-asset-management-platform.html)

**ServiceNow ITOM Agent Client Collector(ACC) / Discovery**
- ACC-V(Visibility) 모듈: Enhanced Inventory, Serial Numbers, Storage Devices, File Systems, Network Adapters, TCP Connections, Running Processes, Installed Software, Local User. Chocolatey, Click-to-Run, winget 등 MSI 외 설치원의 소프트웨어도 발견. push 기반 모델이라 자격증명 저장/예약 스캔 없이 CMDB에 등록하며, 아웃바운드만 허용된 격리망에서도 동작. Linux/Windows/macOS(1.3.0부터) 지원. 반환 값이 영어가 아니면 파싱 실패로 discovery가 실패할 수 있음(한국어 OS 환경에서 유의) — [ServiceNow docs: Exploring ACC for Visibility - Content](https://www.servicenow.com/docs/r/Tm19yM2Ui3~uN9XFBacppg/M_hZRyqHDVuk_D9Vn87N3g); [ServiceNow docs: Exploring ACC-V](https://www.servicenow.com/docs/r/LZHoJyH9VPKmhdIph_6gSw/cFpyX1cVtgbBcIO5fv_Ytg)
- 아키텍처: 에이전트는 MID Server의 websocket 서버(기본 8800, 변경 가능; Linux에서 1024 미만 포트는 root 필요)에 wss://로 접속(acc.yml에 설정), TLS 1.3은 wrapper-override.conf JVM 파라미터로 활성화. API 키로 /api/mid/mon 엔드포인트 테스트 가능. "Update Mid List for All Agents" 잡이 기본 1일 1회 에이전트의 MID 목록을 갱신. 모니터링 체크 간격은 정책의 체크 인스턴스별로 조정 — [ServiceNow docs: configure websocket server on MID Server](https://www.servicenow.com/docs/r/xIukoQY2A2qGfsWn8TUt1A/jIMZFIbN0s0xQCtrIQcIPg); [ServiceNow docs: ACC architecture](https://www.servicenow.com/docs/r/LZHoJyH9VPKmhdIph_6gSw/01bVlU2O0cCM9S5t1ofwvw); [ServiceNow docs: frequency of updating agent MID list](https://www.servicenow.com/docs/r/LZHoJyH9VPKmhdIph_6gSw/nhNMLYaOj0jtBAUocX_cwA)
- SAM과 ACC 연계 문서가 별도로 존재(ACC로 수집한 설치 소프트웨어를 SAM에서 사용) — [ServiceNow docs: Using SAM with ACC](https://www.servicenow.com/docs/r/1zMxrAxr2iK81FYv03BwFA/brdmUXIG47tCPsmYtaxN0Q)
- 에이전트리스 Discovery: WMI로 Windows를 조회하며 MID Server 계정은 대상 로컬 관리자 권한의 도메인 계정 필요, DCOM 응답이 임의 포트를 쓰므로 MID 호스트→대상 전체 포트 접근 필요. PowerShell 3.0~5.1 지원. WinRM/JEA 옵션은 도메인 가입 + PowerShell 5.0/WMF 5.1 + PS Remoting 필요하며 `mid.windows.management_protocol`을 WMI(기본)에서 WinRM으로 변경. ### Inferences
- 자체 구축(.NET 서버 + Windows 에이전트)의 "안전한 기본값"은 업계 관행에서 도출할 수 있다: 에이전트가 항상 아웃바운드로 개시(FlexNet, ACC, NinjaOne, Freshservice, Action1 공통), HTTPS 443 또는 단일 전용 포트(Lansweeper 9524, AssetExplorer 9000, EC 8383, Snow 443 권장), 전체 스캔은 1일 1회 ± 랜덤 지연(Snow randomization, ConfigMgr 240분 지연), 변경 감지 시 델타 push(Freshservice dynamic, ConfigMgr delta), 짧은 heartbeat(Snow 10분 최소, NinjaOne 60초/2분)로 온디맨드 명령 수신.
- 인증서: Snow가 "루트 CA를 PC Trusted Root에 설치" + 선택적 client cert(pfx)를 문서화한 것이 가장 구체적이며, 어느 제품에서도 "certificate pinning"을 명시한 자료는 찾지 못했다. ACC(TLS 1.3 wss), Ivanti(TLS 1.2 필수)처럼 TLS 버전 하한을 명시하는 것이 표준.
- .NET 런타임 선택: 상용 Windows 에이전트는 .NET Framework 4.8(LsAgent), .NET 6(Lansweeper IT Agent), .NET 10(Ivanti Neurons), .NET 8(Freshservice Mac/Linux)로 분산되어 있다. 구형 Windows 7/8 지원이 필요 없다면 최신 .NET(self-contained)으로, 필요하면 .NET Framework 4.8이 현실적 선택이다.
- 로그인 사용자·USB·주변기기: Atera(마지막 로그인 사용자), ACC-V(Local User), Lansweeper(모니터/USB 허브) 등이 수집하지만 "USB 저장장치 이력"을 ITAM 에이전트가 수집한다는 자료는 없었다(DLP/EDR 영역으로 추정).
- 보증 조회는 Lansweeper(Dell/HP/Lenovo/Fujitsu/IBM/Toshiba, 서비스에 하드코딩)와 NinjaOne(지원 벤더 한정, 에이전트 12.0+)이 명시적이며, 서버 측 배치 잡으로 벤더 API를 호출하는 구조로 추정된다.
- ServiceNow ACC의 "비영어 값 파싱 실패" 경고는 한국어 Windows를 대상으로 하는 자체 에이전트 설계 시 로케일 독립적 수집(WMI 속성값 그대로, 날짜/숫자 포맷 고정)의 중요성을 시사한다.
